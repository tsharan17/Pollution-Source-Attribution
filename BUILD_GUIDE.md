## 7 · PM2.5 correction

## 9 · Simulation assumptions to check first

The twin depends on these modelled numbers. Each has a simple bench test. If a measurement falls outside the stated value, re-run the twin with the measured value before trusting the accuracy figures.

| Assumption | Value used | How to measure | Tag |
|---|---|---|---|
| PMS sample heating | +5.0 °C | Laser and fan warm the sampled air, lowering its RH. Measure: PMS vs reference PM2.5 at RH > 80 % | EST |
| PMS RH cap | 95.0 % | Fog/droplet regime not modelled — expect larger errors in fog | EST |
| PMS unit gain spread | σ 0.1 | Co-locate every unit for one day | EST |
| PMS fouling | 0.0003 per day | Re-check monthly against the reference | EST |
| MOX baseline drift | 0.002 ln/day + random walk 0.01/√day | Log clean-air resistance for 2 weeks | EST |
| MOX unit spread | R_ref σ 0.35, sensitivity σ 0.15 | Compare units side by side in clean air | EST |
| MOX noise | 0.01 ln R per reading | Standard deviation of ln R in steady clean air | EST |
| Enclosure losses | PolSo-19 Run A numbers (hooded) | Repeat with the printed enclosure next to an open sensor | EST |

## 10 · Build, flash and verify — step by step

From parts on the desk to a device whose answers can be compared with the simulation.

1. Install STM32CubeIDE (includes CubeMX and the GCC toolchain).
2. New project → Board Selector → NUCLEO-G474RE. Apply the clock and peripheral settings from section 3 and the pins from section 2.
3. Copy firmware_c/polso_fw.c, polso_fw.h, pms7003.c, pms7003.h, model_params.h, pm_cal_params.h (and fastmath.h) into Core/Src and Core/Inc.
4. In main.c: start USART1/USART3 DMA reception, init the BME688 (Bosch BME68x driver) with the heater profile, call fw_init(&state, b0) where b0[10] is the clean-air ln(gas resistance) per heater step (measure it once outdoors in clean air and store it in flash), start LPTIM1 at 1 Hz.
5. On each LPTIM1 wake: pass the UART DMA bytes to fw_uart_rx(), read the BME688 step, call fw_tick(); every 30 s it fills fw_result_t — write it to the SD card and LPUART1.
6. Bench test 1 — parser and maths: run firmware_c/sil.exe on a recorded stream on the PC and on the board (feed the same bytes over the VCP); outputs must match line for line.
7. Bench test 2 — timing: build firmware_c/bench/dwt_bench.c, read the DWT cycle counter, and enter the numbers in stm32_twin/compare_measured.py (see stm32_twin/MEASURE_ON_BOARD.md).
8. Bench test 3 — current: remove JP6, put a multimeter / power profiler in series, compare with the STM32 tab's budget.
9. Co-location: place the device next to a reference PM2.5 monitor (BAM / TEOM or a calibrated optical monitor) for ≥ 7 days. Log both.
10. Fit the PM2.5 correction with polso_twin/pmcal.py on the co-location data, export pm_cal_params.h, re-flash.
11. Source labels: keep a diary of known events (traffic peak, a nearby fire, dust) and compare with label10; verify/ scripts compute the agreement.
12. Compare everything with the simulation: python run_verification.py — any number outside the twin's band is a model error to fix before trusting the map.
